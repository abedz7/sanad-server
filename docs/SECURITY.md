# Sanad server — threat model

lives (file:line at the time of writing — anchors are stable function/constant names if lines
drift), and the test that proves it. Verified additionally by a live curl audit against a running
server (dev build **and** the compiled `dist/` under `NODE_ENV=production`) — transcript summary at
the bottom.

## Live audit (Phase 5) — what was actually run

Executed with curl against a seeded, running server; sections (g)/(i) re-run against the compiled
`dist/server.js` with `NODE_ENV=production`:

- **(a)** all 14 admin routes with a user token → `403 FORBIDDEN`, every one.
- **(b)** all 8 owner routes against another user's ticket → `404`, byte-identical (after
  normalising `requestId`) to the same route with a non-existent id.
- **(c)** `{"$gt":""}` top-level, a nested dotted key, and a `$gt` **query** key → `400`.
- **(d)** 6 MB upload → `413 UPLOAD_REJECTED`; `MZ`-prefixed file named `.png` with a declared image
  type → `415 UPLOAD_REJECTED`.
- **(e)** wrong password / unknown email / locked account → three `401`s, bodies byte-identical
  after normalising `requestId` (the id necessarily differs per request).
- **(f)** every response body captured during the audit grepped: zero hits for `passwordHash`,
  `tokenHash`, `failedLoginAttempts`, `lockedUntil`, `__v`, `storedKey`.
- **(g)** production dist: 404 and validation error bodies contain no `stack`.
- **(h)** `npm audit --audit-level=high` (and plain `npm audit`): 0 vulnerabilities.
- **(i)** no `x-powered-by` and `nosniff` in dev and production; `Strict-Transport-Security`
  present in production (helmet sends it always; it only takes effect behind TLS).
- **(j)** refresh token presented twice → second use `401` **and** the rotated successor `401`
  (family revoked).

One incidental finding: the audit script itself was rate-limited mid-run (10 login attempts/15 min
per IP) — the limiter firing against its own auditor, which is the control working, not a defect.
Nothing in (a)–(j) required a code change.

## Known limitations (accepted, with reasoning)

- **Registration leaks account existence.** `POST /auth/register` returns `409 CONFLICT` for a
  taken email. Without email verification there is no way to both register users and hide this;
  the standard mitigation (verification emails) needs a mail provider (PLAN D2). Login and logout
  do **not** leak existence.
- **Local storage driver is single-node.** Files on one machine's disk; no replication, no shared
  access across instances. The `StorageAdapter` seam plus `STORAGE_DRIVER=s3` is the production
  path.
- **No real malware scanning.** `NoopScanner` marks uploads `skipped` — honestly unscanned. The
  ClamAV adapter is a documented stub; magic-byte checks validate format, not safety.
- **No multi-document transactions.** Ticket writes and their history events are two sequential
  writes (PLAN D3); a crash between them can lose one event (logged with requestId when the append
  itself fails). Upgrade path: single-node replica set + `withTransaction`.
- **Rate limiting is in-memory per process.** Counters reset on restart and are not shared across
  instances; behind a load balancer each node enforces its own window. Production at scale would
  move the store to Redis. Related: `trust proxy` is set to exactly 1 hop in production — correct
  behind one reverse proxy, must be revisited for other topologies.
- **Role changes propagate within ≤15 minutes.** Role is read from the access token (deletion is
  checked per-request, role is not); role mutation is not a feature of this system.
- **Login timing equalisation is best-effort.** The dummy argon2 verify dominates, but DB lookup
  variance remains; not asserted in tests because timing tests are inherently flaky.
- **HSTS is advisory until TLS terminates in front.** The header is always sent; it protects
  nothing over plain HTTP in local dev.
